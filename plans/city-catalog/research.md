## 2. Сравнение источников

| Источник | Сильные стороны | Ограничения для проекта | Решение |
| --- | --- | --- | --- |
| GeoNames bulk | Идентификаторы записей, координаты, коды территорий, feature codes, языковые варианты, downloadable snapshot; CC BY 4.0 | Не гарантирует полноту/безошибочность; порог населения отсекает мелкие места; нужны фильтрация и русские names | Основной источник: cities500 + ограниченные языковые aliases + проверяемые исключения |
| SimpleMaps World Cities | Простой CSV с координатами и ID; Basic бесплатный, CC BY 4.0 | Basic ориентирован на заметные города; платные наборы имеют ограничения перераспространения; русские названия требуют отдельного решения | Запасной вариант, преимуществ перед GeoNames для этого сценария недостаточно |
| dr5hn countries-states-cities | Готовая административная иерархия, IDs, offline exports, поддерживаемый проект | ODbL, собственное версионирование идентичностей и миграции; совместимость русских названий/покрытия отдельно проверять | Возможная альтернатива, не смешивать с GeoNames в первом выпуске |
| Публичный Nominatim | Подходит для некоторых отдельных пользовательских геокодинговых запросов | Его правила запрещают autocomplete и систематическое собирание списков | Не использовать для нового автоселекта и массовой миграции |

Источники: [GeoNames export](https://download.geonames.org/export/dump/readme.txt), [GeoNames terms](https://www.geonames.org/export/), [SimpleMaps](https://simplemaps.com/data/world-cities), [dr5hn README](https://github.com/dr5hn/countries-states-cities-database), [политика публичного Nominatim](https://operations.osmfoundation.org/policies/nominatim/).

## 3. Прямые измерения архивов

Скачаны публичные ZIP-файлы с официального сервера 2026-10-22. Размеры — десятичные MB, не MiB. Значения после фильтра относятся к предложенному allowlist, до загрузки языковых aliases и проверенных исключений.

| Набор | Архив, байт | TSV, байт | Строк в архиве | После allowlist |
| --- | ---: | ---: | ---: | ---: |
| cities1000 | 11 077 563 | 32 022 137 | 171 572 | 161 881 |
| cities500 | 13 900 649 | 41 716 248 | 236 632 | 225 823 |

SHA-256, состав feature codes и проверки мест находятся в [cities500-profile.json](evidence/cities500-profile.json) и [cities1000-profile.json](evidence/cities1000-profile.json). Повторить измерение можно [скриптом](evidence/profile-geonames.py), передав локальный ZIP, URL источника и дату наблюдения. Архив обновляется: новый хеш и другое число строк не означают ошибку скрипта.

Для cities500 дополнительно сформирован JSON из 10 полей: source ID, name, asciiName, country code, admin1 code, lat/lon, population, timezone, feature code. Он занимает **50 198 338 байт**, gzip — **6 504 558 байт**. Это демонстрационная сериализация всех исходных строк, без RU-таблицы, а не рекомендуемый клиентский payload.

Эти измерения **не определяют** размер PostgreSQL, индексов, JS heap или RSS импортёра. Предыдущая оценка БД 30–80 МБ не подтверждена. До A2 нельзя заявлять конкретный установленный размер. Для планирования предусмотреть отдельный замер таблиц, aliases, индексов, временных файлов, WAL и peak RSS. Импорт языковых данных выполнять потоком, сохраняя лишь строки для выбранных ID.

## 4. Покрытие и неоднозначности

Проверка: точное совпадение primary/ascii/одного alias, без учёта регистра, с фильтром countryCode. Язык alias при такой проверке неизвестен: это **не** проверка предпочтительного русского имени.

| Запрос и территория | Результат в cities500 | Следствие |
| --- | --- | --- |
| Tokyo, JP | GeoNames 1850147 | Есть базовая запись Токио |
| Hakone, JP | 1863357 | Посёлок покрывается без требования юридического статуса города |
| Miyajima, JP | 1856798, PPL | Есть населённый пункт с этим именем. Совпадение строки не доказывает, что старое значение обозначало именно его, а не остров |
| Артыбаш, RU | 1511364 | Небольшие места из текущего сценария покрываются |
| Териберка, RU | 483379 | Есть запись; численность источника не равна актуальной переписи |
| Hiroshima, JP | 1862415 и alias у 2130054 | Все aliases нельзя считать одинаково надёжными; исторические/альтернативные имена влияют на разрешение |
| Тайбэй, TW / Гаосюн, TW / Гонконг, HK | 1668341 / 1673820 / 1819729 | Нужна явная связь существующих country ID с кодами TW/HK, без объединения по соседству или переводу имени |

В cities500 найдено **17 187** групп повторяющихся primary names; в них **53 277** записей. Это только совпадения primary names без учёта регистра, а не полный подсчёт всех коллизий aliases.

По [классификатору GeoNames](https://www.geonames.org/export/codes.html) исключаем `PPLX`, `PPLQ`, `PPLH`, `PPLW`, `PPLCH`, `PPLS` из базового списка. Предложенный allowlist: `PPL`, `PPLA`, `PPLA2`, `PPLA3`, `PPLA4`, `PPLA5`, `PPLC`, `PPLCD`, `PPLG`, `PPLF`, `PPLL`, `PPLR`, `STLMT`. Последний сохраняет тип источника; приложение не выводит из него политическую классификацию территории.

`cities500` не обеспечивает все деревни, острова, горы и национальные парки. Для существующих туристических направлений вне базового набора нужен небольшой **проверенный список внешних GeoNames ID** с типом и источником. Не сопоставлять «Бали» с Денпасаром автоматически. Полноценный мировой каталог POI выходит за рамки этой миграции.

## 5. Поиск и нормализация

PostgreSQL 16 поддерживает `pg_trgm` с GIN/GiST. Для шаблонов без извлекаемых триграмм индекс может сканироваться целиком. Поэтому короткие запросы должны иметь отдельный prefix-путь; триграммы не решают автоматически транслитерацию и не доказывают идентичность географических объектов. [Документация PostgreSQL 16](https://www.postgresql.org/docs/16/pgtrgm.html).

Рекомендация: lowercase/NFKC/пробелы для поисковых ключей; проверенная обработка ё/е и диакритики в дополнительном ключе; исходное имя не переписывать. При миграции совпадение по агрессивно нормализованному ключу — кандидат, а не доказательство. Предпочтительные русские названия брать из языково размеченного alternateNamesV2, не генерировать через LLM и не определять язык только по кириллице.

## 6. Границы доказанности

- Подтверждены исходный код перечисленных путей, реальные размеры/строки двух архивов и точечные совпадения aliases.
- Нет аудита актуальной production БД; неизвестны доля auto-resolve, список отсутствующих направлений и реальный объём данных пользователя.
- Нет измерения PostgreSQL, RU-покрытия или latency; это обязательные работы A0/A2/A3.
- Не проверены клики текущего UI, устройства, native offline, CI: здесь исследование и план, не готовая реализация.
- Исследование не давало разрешения применять миграцию к production или изменять уже существующие пользовательские записи.
