# A8: Obsidian import и AI trip

Статус: **partial; resolver интегрирован в importer/core и AI-trip, внешние сценарии не проверялись**

Дата: 2026-10-22

## Сделано

- Общая `resolveCityIds` в `tools/obsidian-importer/src/lib/import-trip.ts` разрешает города до создания новой поездки. Однозначный exact match берёт canonical ID; raw city strings не отправляются как новые места.
- Для неоднозначных/не найденных городов core требует явного выбора или mapping. Без решения бросает `GeoCityNeedsInputError` прежде любой поездочной записи.
- CLI использует публичные `geo/places/resolve`, `search`, `by-ids`. Интерактивный режим показывает search candidates, а `--yes` без manifest безопасно останавливается.
- Добавлен scoped JSON mapping `version: 1` с точным исходным `label` и проверяемым `placeId`, опция `--city-mapping`. Отклоняются несуществующие/retired ID, дубли ID и подписи manifest, которых нет в текущем наборе.
- CLI синхронизирует `cityIds` и делает resolver до подключения к существующей поездке/создания новой. Ошибка записи метаданных с `cityIds` завершает работу до импорта остальных сущностей; новую пустую поездку удаляет.
- Server AI использует тот же `importTripFolderCore` через `InProcessTransport`; его update теперь проходит `tripService.update`, а не обходит валидатор repository напрямую. Неоднозначное сопоставление завершает задачу `needs_input` без создания поездки.
- Авиасегменты проходят server-side exact resolver при импортном section write; только после exact match сервер проставляет `departureCityId`/`arrivalCityId` и каноническую подпись. Неоднозначные подписи AI-trip также становятся `needs_input`.
