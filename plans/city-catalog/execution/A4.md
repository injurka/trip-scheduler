# A4: серверные ID bindings и совместимость

Статус: **partial; основные runtime write/read paths реализованы, живая БД не проверялась**

Дата: 2026-10-22

## Сделано

- Поездки создаются со списком `cityIds`; связи записываются в `trip_geo_places` вместе с проекцией `trips.cities`. Единая гидратация добавляет `cityRefs` и `unresolvedCities` в list, byId, withDays, shareSlug и user-list чтение.
- PATCH со старыми неизменёнными `cities` сохраняет текущие links. Новый текстовый список разрешается только точным уникальным совпадением; ambiguous/not-found получает `BAD_REQUEST`, а не создаёт произвольное место. Если присланы ID и подписи, сервер проверяет их порядок и соответствие.
- Highlights и отзывы канонизируют подпись по ID; старый текст разрешается только однозначно в контексте страны. Отзывы сохраняют ссылку при частичном обновлении; для highlights добавлена полноценная edit mutation, ранее UI изменения не сохранял.
- Вложенные flight fields в JSON проверяются на create/update: ID проверяется против каталога, подпись берётся с сервера, изменённое legacy-название проходит только точный уникальный resolver. Неизменённые прежние строки остаются читаемы.
- `geo.resolveCity` предоставляет точный resolver для импортёров и старых write paths. Для стран importer показывает exact unique matches и заполняет `countries.source_code` только при явном `--apply`; неоднозначные страны остаются без связи.

## Ограничения и проверка

- Backfill существующих trip/profile/flight labels ещё не реализован (A10). Старые trip labels уже отдаются как unresolved и могут быть сопоставлены владельцем в edit UI.
- Миграции не запускались на локальной/пользовательской БД и каталог не импортировался. Из-за этого FK, country mapping и resolver на реальных строках пока не подтверждены.
- Server `bun run typecheck` проходит. Тесты и live API не запускались.
