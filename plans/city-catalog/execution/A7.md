## Сделано

- Добавлено `trips.weather_by_place_id` с additive Drizzle migration `0017_known_joshua_kane.sql`. Старый `weather_data` остаётся совместимой проекцией.
- Погодный API принимает `placeId` для одного города или `placeIds` для выбранного набора. Сервер проверяет, что ID привязаны к этой поездке; старый `city` оставлен только для прежних клиентов.
- ID-генерация использует имя и координаты каталога, получает климатические нормы по координатам и не вызывает внешний геокодер по названию. Новые значения кэшируются по `(placeId, month, generationVersion)`; fingerprint включает географические входы и версию генерации. Upsert атомарен по составному ключу.
- Погодный виджет выбирает места по ID и использует `weatherByPlaceId`; старый текстовый `weatherData` читается безопасно, только когда имя не неоднозначно. Повторная генерация и batch используют ID.
- Карта обзора и диалог городов берут координаты выбранных мест из refs. Nominatim остаётся только для старых поездок без refs. Подписи одноимённых мест в обзоре/текстовом экспорте дополняются страной.
- Автозагрузка при редактировании поездки больше не пробует находить ID-погоду по небезопасному совпадению старого текстового cache key.
