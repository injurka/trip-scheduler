# A3: серверный поиск по каталогу

Статус: **partial**

Дата: 2026-10-22

## Сделано

- Добавлен публичный tRPC `geo`: состояние каталога, поиск и гидрация по ID. Поиск использует активную готовую версию, нормализованные русские/английские/исходные имена, точное совпадение выше префиксного, preferred-name, популярность и лимит 1–30. На один place возвращается одна строка даже при нескольких совпавших aliases.
- Country filter принимает source `countryCode`, а legacy `countryId` работает только при явном отображении в `geo_catalog_countries.legacyCountryId`.
- Поддерживается список до 100 ID для восстановления выбранных мест; retired records доступны через get-by-IDs, но не выдаются для нового поиска.
- Добавлен клиентский API repository `db.geo`, типы `GeoPlaceRef`, search result и catalog status.
- Для prefix пути используется PostgreSQL B-tree `text_pattern_ops` в миграции `0015_daffy_inertia.sql`. Никаких данных на клиенте не бандлится.

## Ограничения

- Добавлен `geo.resolveCity`: точное нормализованное разрешение старого label с country/region/kind context. Однозначное совпадение возвращает ID; несколько совпадений получают `needs_review`, пустой результат — `unresolved`. Fuzzy matching не используется.
- Search endpoint и resolver не проверялись на наполненной PostgreSQL. Время ответа, collation и query plan пока неизвестны.
- Основная серверная проверка ID описана в A4; live API не подтверждён.
- Ни миграции, ни загрузка каталога не запускались на пользовательной БД/Swarm; API пока не имеет импортированных строк.
