# GPS-трекинг и воспроизведение дня

Android Foreground Service получает Fused Location Provider фиксы и состояние Activity Transition API.
Клиент сохраняет принятые измерения с их исходными координатами, скоростью и сигналом устройства.
Исходные точки остаются доступными для повторной обработки; отфильтрованные при сборе или ранее
удалённые измерения восстановить невозможно.

## Общая обработка

Алгоритмы находятся в `packages/track-processing`:

1. `prepareTrack` проверяет координаты и точность, сортирует и дедуплицирует точки внутри сессии,
   разделяет сессии и разрывы записи, удаляет GPS-выбросы.
2. `collapseStayPoints` подтверждает остановку после 90 секунд и минимум четырёх фиксов.
   Радиус: медианная accuracy × 1.5, ограниченная 8–35 м. Минимум 85% окна должны лежать внутри.
   Сдвиг центров начала/конца окна и сигнал движения защищают медленную ходьбу от схлопывания.
3. Центр — взвешенная геометрическая медиана. После подтверждения он фиксируется.
   Уход подтверждают три фикса за минимум 6 секунд вне расширенного радиуса или с сигналом движения.
   Точки начала ухода сохраняются. Большой пробел наблюдений не считается доказанным покоем.
4. `smoothMovingPoints` сглаживает движущиеся участки с весом измерения по accuracy;
   на границах остановок фильтр сбрасывается.
5. `processDayTrack` сохраняет остановки как два одинаковых положения с разным временем,
   нулевой дистанцией и отдельной классификацией. Движение классифицируется между остановками;
   RDP применяется после расчёта дистанции.

Пороговые значения — настраиваемые эвристики, а не гарантия точности. Accuracy Android означает
оценочный радиус 68%, не предельную ошибку. Распознавание остановки запаздывает на время окна;
после подтверждения недавняя геометрия корректируется ретроспективно.

## Сервер и история

`tracking.service.ts` использует тот же пакет для сегментов, карты дня и сводок.
Чтение дня и сводок заново обрабатывает сохранённые измерения, поэтому старые записи получают
новый алгоритм без изменения схемы БД. Чтение не перезаписывает сегменты всей сессии частью дня.
Цена такого подхода — вычисление по точкам выбранного периода; при больших объёмах нужен
версионированный кэш обработки.

## Интерфейс

- «Маршрут»: обработанная линия, отдельные маркеры «Пауза N мин», область разброса;
  попап показывает начало, конец и количество измерений. Центр — оценка, не установленное место/POI.
- «Исходные точки»: сохранённые измерения без декоративного сплайна, включая видимый дрейф.
  Удаление действует на исходную точку и пересчитывает день. У агрегированной остановки
  кнопки удаления отдельного измерения нет.
- Плеер использует обработанные координаты и реальные времена; во время остановки неподвижен,
  скорость равна нулю. Перемотка к движению сохраняет длительность остановки.
- Живая телеметрия пересчитывает последние три минуты и может уточнить дистанцию после
  подтверждения остановки. Серверный полный расчёт остаётся итоговой сводкой.

Привязка к дорожной сети (map matching) в этот алгоритм не входит. Для неё нужен отдельно
настроенный сервис с профилями пешком/велосипед/авто и проверкой качества совпадения.
Координаты не отправляются стороннему сервису привязки автоматически.

## Проверка

`bun run --cwd packages/track-processing test` покрывает дрейф кафе, выход из остановки,
медленную ходьбу, пешую петлю, одиночный скачок и границы сессий/пропуски, а также прежние
регрессии классификации.

Проверка на устройстве: прогулка → 20 минут в помещении → прогулка, затем повтор с
заблокированным экраном и без сети. Проверять начало/конец остановки, дистанцию, плеер
и сохранение точек после возобновления приложения. Без Android SDK/device эти проверки
не заменяются TypeScript-тестами.
